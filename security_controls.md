# Registre des contrôles de sécurité — InduSense API (M26)

Branche `ludovic-bourreau`, jalon 04. Établi le 29/09/2026.
Règle : un contrôle n'est « Implémenté » que s'il est prouvé par un **test rejouable** (`uv run --frozen pytest tests/test_api.py tests/test_security.py -q` → 10 passed ; `tests/test_predict_image.py` → 7 passed). Aucune clé ni valeur de `.env` dans ce document.

| Contrôle | Statut | Preuve actuelle | Risque résiduel | Action suivante |
|---|---|---|---|---|
| Auth | Implémenté | `require_api_key` (`src/indusense/api/main.py`) : en-tête `X-API-Key` absent ou faux → **401** ; tests `test_missing_api_key_returns_401` (`tests/test_api.py`, `tests/test_predict_image.py`) | une seule clé partagée, sans identité par client ; valeur par défaut `dev-key` publique si `INDUSENSE_API_KEY` n'est pas défini ; comparaison `!=` non constante en temps ; pas de rotation | refuser le démarrage en production sans `INDUSENSE_API_KEY` ; comparer avec `secrets.compare_digest` ; une clé par client consommateur, avec rotation |
| Validation | Implémenté | schémas Pydantic v2 (`src/indusense/api/schemas.py`) : ≥ 7 relevés, `temperature` ∈ [-20 ; 200], `pressure_bar` ∈ ]0 ; 400] ; `normalize_machine_id` ; image : liste blanche PNG/JPEG + signature binaire → **422** ; tests `test_insufficient_readings_returns_422`, `test_predict_invalid_machine_id_returns_422`, `test_fake_png_is_rejected_by_signature` | contrôle de **forme et de bornes**, pas de **plausibilité** : une série inventée mais bornée (entrée adversariale) est acceptée ; `machine_id` non vérifié contre le référentiel `machine.sql` | contrôle de cohérence temporelle des relevés ; vérifier `machine_id` contre la liste des machines connues ; tests d'entrées adversariales |
| Rate limit | Implémenté | `rate_limit` via `rate_limit_dependency` (`src/indusense/api/security.py`) : 60 requêtes / 60 s / IP → **429** ; politique non surchargeable par l'URL ; tests `test_rate_limit_blocks_after_limit`, `test_rate_limit_policy_is_not_exposed_as_query_parameters` (`tests/test_security.py`) | compteur **en mémoire d'un seul processus** : remis à zéro au redémarrage, non partagé entre workers ou conteneurs ; fondé sur l'IP vue par l'API (derrière un proxy, tous les clients partagent la même IP) ; mémoire non bornée si les IP sont nombreuses | compteur partagé (par exemple Redis) ou limitation au niveau du reverse proxy ; clé de limitation = client authentifié plutôt qu'IP |
| Taille payload | Implémenté | middleware `limit_body_size` (`src/indusense/api/security.py`) : `Content-Length` > 64 Kio (`MAX_BODY_BYTES = 64 * 1024`) → **413** ; `Content-Length` illisible → **400** ; tests `test_payload_too_large_returns_413`, `test_invalid_content_length_returns_400` | repose sur le `Content-Length` **déclaré** : une requête sans cet en-tête (transfert par blocs) n'est pas contrôlée par ce middleware (non testé) | compter les octets réellement lus, ou limiter la taille au reverse proxy ; ajouter un test sans `Content-Length` |
| Audit logging | Planifié v0 | **aucune** : l'API n'écrit aucun journal (aucun logger dans `src/indusense/api/`) ; le `X-Request-ID` corrèle les requêtes mais **n'est pas** un audit log | répudiation : impossible de reconstituer qui a reçu quelle prédiction, de quel modèle, quand | émettre un événement structuré par prédiction (horodatage, `X-Request-ID`, route, code HTTP, `model_version`, décision) **sans clé, sans payload, sans donnée personnelle** ; test dédié vérifiant la présence de l'événement et l'absence de ces champs sensibles |
